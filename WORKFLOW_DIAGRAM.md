# 📊 Git 工作流程可视化

## 🌳 分支结构图

```
原作者仓库 (Zafer-Liu/Data-Analysis-Agent)
    ↓ (fork)
你的Fork (ebkristan/Data-Analysis-Agent)
    │
    ├─ main 分支          ← 只读，用于同步上游
    │   ↓ (创建)
    └─ custom-dev 分支    ← 你的开发分支
        ↓ (可选：创建功能分支)
        ├─ feature/ui-改进
        ├─ feature/新数据源
        └─ feature/api-扩展
```

## ⬇️ 同步上游更新流程

```
┌──────────────────────────────────────────────────┐
│  原作者发布新版本                                 │
│  Zafer-Liu/Data-Analysis-Agent (main)            │
└───────────────────────┬──────────────────────────┘
                        ↓ upstream
        ┌───────────────────────────────┐
        │  1. 切换到 main 分支          │
        │     git checkout main         │
        └───────────┬───────────────────┘
                    ↓
        ┌───────────────────────────────┐
        │  2. 获取上游更新              │
        │     git fetch upstream        │
        └───────────┬───────────────────┘
                    ↓
        ┌───────────────────────────────┐
        │  3. 合并上游到本地 main       │
        │     git merge upstream/main   │
        └───────────┬───────────────────┘
                    ↓
        ┌───────────────────────────────┐
        │  4. 推送到你的 Fork           │
        │     git push origin main      │
        └───────────┬───────────────────┘
                    ↓
        ┌───────────────────────────────┐
        │  5. 切换回开发分支            │
        │     git checkout custom-dev   │
        └───────────┬───────────────────┘
                    ↓
        ┌───────────────────────────────┐
        │  6. 合并 main 到开发分支      │
        │     git merge main            │
        └───────────┬───────────────────┘
                    ↓
        ┌───────────────────────────────┐
        │  7. 解决冲突（如果有）        │
        │     手动编辑冲突文件          │
        │     git add .                 │
        │     git commit                │
        └───────────┬───────────────────┘
                    ↓
        ┌───────────────────────────────┐
        │  8. 推送更新                  │
        │     git push origin custom-dev│
        └───────────────────────────────┘
```

## 🔀 冲突解决流程

```
                合并时发现冲突
                      ↓
        ┌──────────────────────────┐
        │  git status              │
        │  (查看冲突文件列表)       │
        └──────────┬───────────────┘
                   ↓
        ┌──────────────────────────┐
        │  打开冲突文件            │
        │  找到冲突标记：          │
        │  <<<<<<< HEAD            │
        │  你的代码                │
        │  =======                 │
        │  上游代码                │
        │  >>>>>>> upstream/main   │
        └──────────┬───────────────┘
                   ↓
        ┌──────────────────────────┐
        │  决策：                  │
        │  ┌────────────────────┐  │
        │  │ 保留你的代码？     │  │
        │  │ 保留上游代码？     │  │
        │  │ 两者都保留？       │  │
        │  │ 重写？             │  │
        │  └────────────────────┘  │
        └──────────┬───────────────┘
                   ↓
        ┌──────────────────────────┐
        │  手动编辑，删除标记      │
        │  保存文件                │
        └──────────┬───────────────┘
                   ↓
        ┌──────────────────────────┐
        │  git add 冲突文件.py     │
        └──────────┬───────────────┘
                   ↓
        ┌──────────────────────────┐
        │  git commit -m "解决冲突"│
        └──────────┬───────────────┘
                   ↓
        ┌──────────────────────────┐
        │  git push                │
        └──────────────────────────┘
```

## 📦 文件修改策略

```
你要添加新功能？
        │
        ├─ 是核心逻辑？
        │  │
        │  ├─ 是 → 修改原文件，但用注释标记
        │  │      ┌────────────────────────────┐
        │  │      │ # === CUSTOM START ===    │
        │  │      │ 你的代码                  │
        │  │      │ # === CUSTOM END ===      │
        │  │      └────────────────────────────┘
        │  │
        │  └─ 否 → 创建扩展文件
        │         ┌────────────────────────────┐
        │         │ extensions/my_feature.py  │
        │         └────────────────────────────┘
        │
        └─ 是配置？
           │
           └─ 创建自定义配置
              ┌────────────────────────────┐
              │ config/custom/settings.py │
              │ .env.custom               │
              └────────────────────────────┘
```

## 🎯 三种开发模式对比

### 模式 1：直接修改（不推荐）

```
原始代码 → 直接修改 → 上游更新 → 💥 冲突！
```

**问题**：每次更新都可能冲突

---

### 模式 2：扩展模式（推荐）

```
原始代码 → 保持不变
    ↓
extensions/
    ├─ my_tool.py
    └─ my_api.py
    
上游更新 → ✅ 无冲突！
```

**优点**：更新时不会影响你的扩展

---

### 模式 3：混合模式（平衡）

```
原始代码 → 少量标记修改 → 上游更新 → 手动检查标记
    ↓
extensions/ → 大部分自定义
```

**优点**：灵活度最高，冲突最少

## 🚀 快速命令参考

### 创建开发分支
```bash
git checkout -b custom-dev
git push -u origin custom-dev
```

### 日常提交
```bash
git add .
git commit -m "feat: 描述"
git push
```

### 同步上游
```bash
git checkout main
git fetch upstream && git merge upstream/main
git push origin main
git checkout custom-dev
git merge main
git push
```

### 查看状态
```bash
git status           # 查看修改
git log --oneline    # 查看历史
git diff             # 查看详细改动
git remote -v        # 查看远程仓库
```

### 撤销操作
```bash
git reset --soft HEAD~1    # 撤销提交（保留修改）
git stash                  # 暂存当前修改
git stash pop              # 恢复暂存
```

## 📅 推荐的工作节奏

### 每天
- 早上：`git pull` 拉取团队更新
- 开发中：频繁小提交
- 晚上：`git push` 推送到远程

### 每周
- 周一：同步上游更新
- 周五：清理无用分支，整理代码

### 每月
- 创建备份分支
- 回顾和重构代码
- 更新文档
